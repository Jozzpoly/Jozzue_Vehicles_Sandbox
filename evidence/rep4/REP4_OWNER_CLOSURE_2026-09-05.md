## 4. What Rep4 actually earned

Rep4 provides bounded evidence that the current research substrate can compose:

`geometry-derived revolute arms + spherical upright + real fixed tie + real spring/damper + real donor visual projection`

while preserving a single causal authority path.

It also demonstrated:

- multiple mechanically distinct hardpoint classes can be directly edited in one 3D BUILD space;
- edited geometry can enter the same native Box3D PLAY path;
- visible PLAY can consume native snapshots rather than a second decorative suspension solver;
- exact authored BUILD state can survive PLAY and return unchanged;
- one real Blockbench/glTF component can be projected from the live mechanism without becoming physics authority;
- permissive weird geometry is possible without automatic normalization.

These are useful implementation capabilities and donor capital.

## 6. Root-cause interpretation

Rep3 exposed `prototype too sparse to earn feel judgement`.

Rep4 increased implementation richness but largely preserved the same interaction grammar:

`prebuilt topology → select exposed point → translate/numeric edit → observe derived geometry → PLAY canned excitation → return`

This widened the parameter/hardpoint space but did **not** materially widen the construction space.

The most important missing capability is therefore not another hardpoint class. It is the ability to make **structural construction decisions** such as creating, removing, reconnecting or replacing meaningful mechanical relations/components.

This is consistent with external construction-kit / direct-manipulation references used only as support research:

- Shneiderman: visible objects plus rapid, incremental, reversible direct manipulation;
- Resnick / Silverman: low floor, wide walls, many paths and making powerful ideas salient rather than forced;
- Trailmakers: simple connection semantics yielding combinatorial construction space;
- Besiege / Scrap Mechanic / GearBlocks: direct placement and connection of simple functional parts produces machine-building breadth greater than a fixed topology with more exposed numbers.

These references do not have architecture authority over JV.

## 7. Development-process correction

Rep4 also exposed a process inefficiency.

A large amount of machine hardening was performed before the next Owner judgement: Stage A, robustness work, B1 correspondence, B2 interaction, B3 integration and several browser fixes. That rigor produced trustworthy evidence, but it also hardened an interaction family that the Owner still judged as fundamentally poor.

Retained correction:

> **Do not spend integration-grade validation on an interaction idea before it has earned enough Owner value to justify hardening.**

Next development should explicitly separate three prototype roles:

1. **causal / implementation lab** — rigorous, narrow, machine-heavy probes only for real technical unknowns;
2. **interaction / experience spikes** — fast, disposable, comparative prototypes testing construction grammar and creative breadth, allowed to be non-physical or partially simulated when clearly labeled and when no causal claim is being made;
3. **integration specimens** — combine a promising interaction grammar with qualified causal mechanics only after both sides have earned their own evidence.

This is not permission to fake causal mechanisms in an Owner test. A look-and-feel spike must clearly state that it is testing interaction only. Once a mechanism is presented as physically causal, the existing single-authority rule applies.

## 8. Immediate post-Rep4 frontier

Do not implement Rep4 B4/B5 or incrementally enlarge the same corner.

The next bounded program should be a **small set of competing construction-grammar spikes**, not one more integrated suspension prototype.

The first comparison should test at least two materially different ways to create/edit actual relations/components, for example:

- drag from one physical connection point to another to create/remove/reconnect an adaptive link;
- place a recognizable component, then manipulate/snaps its endpoints into the mechanism;
- a hybrid where component placement and endpoint dragging coexist.

Minimum experiential criterion:

> the Owner must be able to create a configuration that was not already encoded as the apparatus topology, not merely alter coordinates of an existing configuration.

Use real donor visual capital where it improves recognition. Generic rods/tubes may be procedural when they are deliberately the adaptive component being tested rather than a substitute for available real components.

Owner comparison should happen **early**, after lightweight machine/browser smoke and before integration-grade causal qualification.

Only a promising grammar should then be connected to the qualified Rep4/Rep2 causal substrate.
